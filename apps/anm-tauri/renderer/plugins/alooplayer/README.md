# AlooPlayer · 无缝视频循环播放器

一个纯前端（零构建、零依赖）的视频片段连续播放器：把几个视频片段**连着播**，片段之间**无缝衔接、不卡顿**。

## 核心概念：编号 = 连接标签

每个片段维护两个编号：

- 片段 A：起始编号 `1`，结束编号 `3`
- 片段 B：起始编号 `3`，结束编号 `4`

**编号只是连接标签，不映射视频里的帧**。规则只有一条：**所有「起始编号 = 当前片段结束编号」的片段都可无缝接续**——A 结束编号 3 = B 起始编号 3，所以 A 播完后直接接 B。当两个片段在接缝处的画面一致时（比如从同一段长视频上剪下来的相邻两段），切换瞬间画面零变化，视觉上完全无缝。

**片段也可以接续自己**：当某个片段的起始编号 = 结束编号（如 `3-3`）时，它就在自己的可接续列表里，播完自然循环自己——因此循环不需要专门的逻辑，硬循环按钮只是它的快捷方式（保留）。

播放本身没有任何花哨：调用浏览器原生视频能力，每个片段从头播到尾，播完无缝切到下一个。

## 界面布局

```
┌──────────────────────────────┬──────────────────────────┐
│  播放器(舞台)                 │  片段管理(右侧栏)         │
│  · 播放/暂停/停止/进度条      │  · 添加/拖拽/加载演示     │
│  · 当前片段徽章 + 时间        │  · 行式片段卡片列表       │
│  · 下一段信息                 │  · 播放模式按钮(最下方)   │
└──────────────────────────────┴──────────────────────────┘
```

**播放模式按钮在右侧栏最下方**：🔁 循环当前 / ➡️ 顺序接续 / 🎲 随机接续 / 👆 手动接续，可随时点击切换，当前模式高亮并显示说明文字。

## 片段卡片与状态指示

每个片段一行：**缩略图 + 两行信息（名称·时长 / 起始编号·结束编号）+ 删除按钮**。

播放过程中卡片有三种状态指示（不靠边框颜色区分，全部叠加在缩略图上）：

| 状态 | 指示 | 含义 |
|---|---|---|
| 正在播放 | 缩略图上 **▶ 播放图标** | 当前正在播放的片段 |
| 即将播放 | 缩略图上 **⏳ 等待图标** | 下一个将播放的片段（手动点选、或随机/顺序自动选出的） |
| 可无缝接续 | 卡片 **绿色边框**（自动置顶到列表最前） | 起始编号 = 当前片段结束编号（**含自己**：自接续时当前片段也绿框） |

> 绿框和 ⏳ 可以同时出现在同一张卡片上（可接续且被选为下一个）。

## 操作方式

- **添加片段**：点击「＋ 添加视频」或直接拖拽文件到列表区；「🎬 加载演示片段」一键体验
- **编辑编号**：直接修改卡片第二行的「起 / 止」数字（编号只决定连接关系，可任意正整数，不要求连续）
- **播放某个片段**：未播放时点击卡片
- **指定下一段**：播放中点击任意卡片（可接续的优先——绿框置顶）；再次点击已选中的卡片可取消；手动指定在**任何策略下都优先**，播完一次后回到策略默认
- **预览**：点击缩略图（逐帧步进 / 截帧，用于核对接缝画面是否一致）
- **删除**：点击卡片右侧 ✕

## 四种播放策略

| 策略 | 行为 |
|---|---|
| 🔁 循环当前 | 硬循环当前片段（快捷方式；用编号自接续也能达到同样效果） |
| ➡️ 顺序接续 | 自动选可接续的片段（列表顺序取第一个，候选含自己）；无可接续时循环当前 |
| 🎲 随机接续 | 从「起始编号 = 当前结束编号」的可接续片段中随机挑下一个（缩略图 ⏳ 指示，候选含自己） |
| 👆 手动接续 | 必须点击列表中的片段指定下一段；未指定则播完停在最后一帧，弹出选择浮层等待 |

手动点选（播放中点击卡片）在任意策略下都会覆盖一次自动选择。

## 为什么能做到无缝（技术要点）

1. **双缓冲**：两个 `<video>` 元素，前台播放、后台预载。后台预载 = `preload="auto"` + seek 到 0 + 等待 `canplaythrough`（整段数据就绪、首帧已解码可立即显示）。
2. **提前切换**：rAF 轮询前台剩余时间，剩余 ≤ 提前量（`min(300ms, 时长/3)`，对短片段自动收缩）时立即切换——**不等 `ended`**（ended 时刻浏览器画面可能是黑帧）。切换 = 瞬切 opacity（0ms 过渡）+ 后台 `play()` + 角色互换 + 预载下下段。
3. **不黑屏的保证**：后台就绪（canplaythrough）才切换，切换瞬间有现成帧直接显示，没有解码延迟、没有过渡闪烁、没有 ended 黑帧窗口。
4. **兜底**：`ended` 事件仅作最后保障；播放中 2 秒无进度更新（呈现管道偶发停摆）时自动重启当前片段恢复。
5. **流水线**：每段开始播放即按策略预载下一段；切换后立即预载下下段，衔接永远有备而发。

浏览器要求：现代浏览器即可。

## 快速开始

```bash
# 生成演示片段（需要 ffmpeg + drawtext 滤镜）
bash demo/gen-demo.sh

# 任意静态服务器均可（用到了 fetch 与 ES Module，不能用 file:// 打开）
python3 -m http.server 8000
# 或: npx serve .
```

打开 <http://localhost:8000>，点击「🎬 加载演示片段」即可体验：

```
A(1-3) → B(3-4) → C(4-7) → D(7-9) → E(9-11)   主链
A(1-3) → F(3-6)                                 分支（死胡同，演示无可接续时循环）
```

演示片段画面上显示的数字就是**编号**：A 播完（编号 3）直接接 B（编号 3 起），中间没有任何卡顿。试试把策略切到「🎲 随机接续」看它在链上随机游走，或切到「👆 手动接续」点击列表中的片段指定下一段。

## 常见问题

- **衔接处有跳变**：两个片段在接缝处的画面必须真的相同（比如从同一段源视频的相邻位置剪辑）。用「🔍 预览」+ 截帧对比两个片段的接缝画面。
- **编号怎么设**：想让 X 播完后接 Y，就让 Y 的起始编号 = X 的结束编号。编号可以是任意正整数，不要求连续、不要求从 1 开始。
- **演示片段生成失败**：需要 ffmpeg 且编译了 drawtext 滤镜（`ffmpeg -filters | grep drawtext`），系统需有 TTF 字体。
- **音频说明**：演示片段无音轨，方便专注验证画面衔接；引擎本身支持有声片段，切换时声音随画面一同接续（有声片段的衔接流畅度取决于两端音频内容，与视频衔接机制无关）。
